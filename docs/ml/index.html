Machine-learning screener

Release — · built, measured once, and published

The result is negative, and that is the finding. The model does not beat the written rules it was built to improve on. The one quantity this whole exercise was designed to measure — the precision of the review queue the model proposes over cases the rules reject — came back at —.

The candidate was marked experimental on the validation split before the test set was opened, and it stays that way. The rules remain authoritative. Nothing about the map, the headline counts or scope_all changes.

The question

The existing screen is a written rules filter. It is precise, but it is a filter: whatever it rejects is gone. The worthwhile question is whether a model can recover the relevant cases the rules throw away, cheaply enough to be worth a person's time. So the model was never framed as a replacement — it is a review queue over rules-rejected cases, plus a second opinion on accepted ones, and the queue's precision was registered in advance as the primary measurement.

Why the answer is this answer

An interval running from near zero to near one is not a measurement of a model; it is a measurement of a sample too small to tell a useless queue from an excellent one. This is a denominator fact, and it was foreseeable — the same arithmetic set the validation lower bound below the gate and forced the experimental verdict before the test was opened.

Two further constraints are structural. Roughly half of the rules-rejected cases could not be resolved either way by two independent passes reading the written policy — the filing text often does not say enough to decide. And the model sees names only: Colorado's collateral field is a 124-value category list and Connecticut has none.

How the sample was drawn, and how it is weighted

Labelling was drawn, not collected by convenience. Every estimate is weighted by 1 / inclusion_probability per row. The stratum average N_h / n_h is shown below for orientation and is applied to no row — the two disagree here, because the sampling design puts several rates inside a single stratum. A guard requires each held-out stratum's design weights to reconstruct its population exactly; they do.

Labels

The two labelling rounds were produced under different arrangements, so each is stated separately rather than pooled into one sentence — naming either alone would describe rows it does not cover. Labelling used the written policy only; nothing was looked up.

Scored across the whole population

The frozen model was run over every candidate case. The queue below is published as a candidate list, not as a result: the measurement above does not establish its precision.

What would change the result

A test supplement drawn after freezing and stratified on the frozen decision — roughly 800 labels — would narrow the review-queue interval from about 0.59 wide to about 0.09. That is the measurement worth making, and it needs labels, not a better classifier. It was deliberately not taken here: it changes the sampling contract, and opening the test set first forecloses it.
